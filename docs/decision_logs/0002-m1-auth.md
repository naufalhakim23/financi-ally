# 0002: M1 auth

**Date:** 2026-07-21
**Milestone:** M1 (auth)
**Status:** decided, implemented

## Context

M1 deliverable (plan §9): email+password JWT auth with Apple/Google OAuth;
ends when register → login → protected route works, OAuth flow on-device. The
M0 log (D6, D7) deferred the migration runner to M2 and the strict-server flip
to M1; both had to land here; auth needs a `users` table and typed endpoints.
Several M1 forks were left open by the plan and resolved below.

## Decisions

| # | Decision | Chosen | Rejected & why |
|---|---|---|---|
| 1 | OAuth scope | Email+pw fully working + **Google via expo-auth-session** (server-side code exchange); **Apple deferred to M7** | Everything-now (incl. Apple); untestable without Apple dev creds + iOS build; pure-email; Boss wanted a real OAuth demo. Google web-client PKCE flow is testable on `expo start --web` in minutes |
| 2 | Password hash | **argon2id** (64MiB/3/2, OWASP band) | bcrypt; fine but argon2id is the 2026 default; params encoded in-hash so retuning stays backward-compatible |
| 3 | Token model | **Access JWT (HS256, 15m) + opaque refresh (sha256-hashed, rotate-on-use, 30d)** | Access-only; M3 offline sync needs long-lived auth; stateful sessions; JWT is enough for one backend |
| 4 | Google code handling | **Server-side code exchange** (server holds client_secret, `oauth2.Config.Exchange` + userinfo v2) | idToken verification on server; flakier reasoning, more crypto deps, less ergonomic client flow |
| 5 | Migration runner | **golang-migrate embedded** (iofs source, postgres driver via pgx stdlib), **run on boot, fail-closed**; brought forward from M2 (users table needs a home) | plain `psql -f` (sibling convention); Boss picked the versioned runner for up/down tracking |
| 6 | Strict-server | **Flipped on** (M0 follow-up); handler returns typed response objects | stay non-strict; register/login are exactly the typed endpoints strict earns its keep on |
| 7 | Auth middleware | **Path-allowlist** of protected ops (`/auth/me`, `/auth/logout`) over the generated handler | kin-openapi `OapiRequestValidator`; 2 protected ops don't justify the dep yet (ponytail); upgrade when protected surface grows |
| 8 | Refresh storage | **token_hash bytea UNIQUE**, rotate inside one tx (`UPDATE ... RETURNING` guards reuse) | plaintext token / no rotation; single-use rotation is the theft signal for a finance app |
| 9 | OAuth account linking | Same-email user is reused (linked); else OAuth-only user created in one tx | separate OAuth users table; the `oauth_identities` link table already supports N providers per user |
| 10 | Mobile token storage | **expo-secure-store** (keystore/keychain) | AsyncStorage; plaintext token store is a trust-boundary failure |

## Tradeoffs surfaced

- **Path-allowlist auth (D7)** trades a hand-maintained allowlist for zero new
  deps at 2 protected ops. If someone adds a protected op and forgets the
  allowlist, it ships unauthenticated; the comment names the upgrade path
  (spec-derived validator) and the trigger (hand-maintenance becoming a footgun).
- **Refresh rotate-on-use (D8)** costs one extra DB write per refresh and means
  a concurrent double-refresh races (one wins, the other gets 401). Acceptable
  for a personal-finance client; documented so it isn't mistaken for a bug.
- **golang-migrate on boot (D5)** means a bad migration refuses to start the
  server; fail-closed is correct for a stateful backend, but a failing
  migration in prod blocks deploys until fixed.
- **Google server-side secret (D4)** is one more secret to manage and rotate;
  it buys a flow that works identically on web/iOS/Android with PKCE on the
  client and the secret off-device.
